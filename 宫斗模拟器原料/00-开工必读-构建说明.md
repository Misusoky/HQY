# 《带着系统去宫斗》网页版 · 构建说明（给编码 Agent）

## 1. 项目目标

把项目记忆里运行中的文字游戏《带着系统去宫斗》做成一个**适配 iPhone Safari 的单文件 HTML 游戏**。

- 交付形态：一个 `index.html`（内联 CSS/JS，无构建步骤、无外部依赖，双击或部署即玩）。
- 叙事生成：调用 Kimi（Moonshot）大模型 API 实时生成。网页本身不内置剧情文本。
- 本包原料：`02-世界书.md`（固定规则）、`03-叙事文风.md`（文风）、`04-当前存档-v36.json`（续玩导入档）、`05-剧情大事记.md`（历史里程碑）、`01-系统提示词.md`（每次请求发给模型的系统提示词模板）。

## 2. 核心架构

```
┌─────────────────────────────────────────┐
│ index.html                              │
│  ├─ 界面层：宣纸风 UI、状态面板、选项按钮 │
│  ├─ 状态层：游戏状态对象（内存+localStorage）│
│  ├─ 回合状态机：旬首安排→叙事→应对→结算   │
│  └─ API 层：拼装系统提示词+存档→调用模型   │
└─────────────────────────────────────────┘
```

### 2.1 回合状态机（必须严格实现）

每旬（一个回合）状态流转：

1. `FOCUS_SELECT`（旬首安排）：显示当前状态栏 + 生活重心菜单（才艺修习／休养康健／自由活动与社交／宫务经营／子女教育／家族书信，允许自定义）。玩家选定一个重心 → 进入 `NARRATING`。
2. `NARRATING`（第一轮）：把【系统提示词 + 当前存档 JSON + 玩家所选重心】发给模型，请求生成。模型返回结构化结果（见 §4）：
   - 若 `hasEvent: false`：直接渲染正文与结算，`TURN_END`，等待下一旬。
   - 若 `hasEvent: true`：渲染正文与 `options`，进入 `EVENT_CHOICE`，**停下等玩家点选**。
3. `EVENT_CHOICE`：玩家点选 2—4 个选项之一，或提交自定义应对 → 进入 `RESOLVING`。
4. `RESOLVING`（第二轮）：把选择回传模型，请求演绎后果并结算。返回后渲染正文与变化，`TURN_END`。
5. `TURN_END`：显示"本旬变化 + 待续事项"，提供【下一旬】【存档】【查询面板】。

**纪律（写代码时必须遵守）：**
- 有突发事件时绝不自动替玩家选择；选项出现后就停下。
- 每回合只推进一旬，不自动跨旬、不自动进结局。
- 查询类指令（状态／面板／才艺／道具清单／商城等）不消耗回合、不调模型（直接展示本地状态 JSON）。
- 自动存档节点：每 5 旬一次 + 重大变化后（晋升/降位、怀孕、死亡、派系变动、剧情阶段转换），见世界书第 13 节。

### 2.2 本地状态与存档

- 游戏状态即 `04-当前存档-v36.json` 的 schema（读档导入后保存在内存与 localStorage）。
- 每旬结算后：把模型返回的 `statePatch`（见 §4）合并进本地状态（数值做 0—100 边界钳制），再驱动界面刷新。
- 存档槽：至少 3 个手动档 + 1 个自动档，全部存 localStorage；提供**导出 JSON 文件 / 导入 JSON 文件**（导入即覆盖当前状态，导入前弹确认）。开局提供两个入口：【继续（导入 v36 档）】【新游戏】。
- 新游戏：仍调模型，按世界书第 14 节生成开局（朝代参数→主角档案→皇帝→妃嫔派系→首个主线任务），生成后展示主角档案并请玩家确认。

## 3. API 接入

- Endpoint：`https://api.moonshot.cn/v1/chat/completions`，模型 `kimi-k2`（或用户可选的 kimi 系列模型）。
- API Key：首次进入设置页由用户填写，存 localStorage（注明勿分享页面）。所有请求从浏览器直发。
- 请求拼装：
  - `system`：完整拼接 `01-系统提示词.md` 的模板（含世界书全文、叙事文风、当前存档 JSON、输出格式指令）。
  - `messages`：本会话内已发生的叙事与选择历史（至少保留最近 6 旬的摘要 + 当前旬全部消息；超长时压缩旧旬为一句话摘要）。JSON 模式 / `response_format: {type:"json_object"}`。
- 失败处理：网络错误/限流时重试 1 次并提示；解析失败时展示原文并允许"重试生成本旬"。

## 4. 模型输出契约（关键！）

系统提示词中要求模型**只输出 JSON**，字段：

```json
{
  "narrative": "本旬剧情正文（300—800字，第三人称限定视角，无emoji）",
  "haremNews": "后宫动态（可感知公开消息/传闻，无则空字符串）",
  "changes": ["本旬变化条目，如 琴艺+2、银两-5两、韦昭仪好感+3"],
  "hasEvent": true,
  "options": [
    {"id": "a", "text": "选项文字（只写机会与代价，不泄露未发生后果）"}
  ],
  "hasEvent 为 false 时 options 应为空数组": null,
  "todo": ["待续事项更新"],
  "statePatch": {
    "protagonist.skills.琴艺": 33,
    "protagonist.silver": 68,
    "relationships.韦昭仪.value": 88,
    "time": {"era":"元朔","year":5,"month":1,"xun":"上旬"},
    "location": "披香殿侧殿",
    "pending": ["……"],
    "log": "本旬一句话摘要（用于会话历史与存档）"
  }
}
```

- 第二轮（应对结算）返回相同结构，`hasEvent` 恒为 `false`。
- 前端按 `statePatch` 逐键合并（点号路径展开），并钳制数值范围。
- 正文渲染按世界书第 12 节顺序：当前状态 → 本旬安排 → 剧情正文 → 后宫动态 → 本旬变化 → 待续事项 → 下一步。

## 5. 界面要求

详见 `06-界面与交互规范.md`（宣纸风设计令牌、iPhone 适配、各屏幕规格）。要点：
- viewport 适配 + safe-area；正文 17px 起，行高 1.8；选项按钮全宽、可点区域 ≥44pt。
- 底部固定操作栏：【状态】【道具】【商城】【存档】【设置】。
- 状态栏简短，只列本旬变化项，不每旬重复全档。

## 6. 内容边界（写提示词与做兜底时遵守）

世界书第 11 节：无现代概念入戏、无露骨性描写、无上帝视角剧透、血腥仅限黑化>90 极端后果且至多 1—2 次。前端兜底：正文渲染前过滤 emoji 与 markdown 代码块痕迹。

## 7. 验收清单

1. iPhone Safari 打开即玩，竖屏无横向滚动。
2. 导入 v36 档后，状态面板显示：元朔四年十二月末→下一旬进入正月；崔明蘅才人；属性/才艺/银两 68 两/积分 90/关系值与存档一致。
3. 选一旬重心 → 模型返回正文 → 有事件时选项出现且页面停住不自动推进。
4. 应对后变化正确合并，状态栏只显示变化项。
5. 存档/读档/导出/导入 JSON 均可用；每 5 旬自动存档。
6. 查询面板（状态/才艺/道具/商城）不触发模型调用。
