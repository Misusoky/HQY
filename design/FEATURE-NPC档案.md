# FEATURE · NPC 档案系统（双层档案 + 视角解锁）

> 状态：设计已立项，待实现。每认识一个 NPC，系统自动建档；档案分两层，一层驱动言行（后台真相），
> 一层渐进解锁（主控视角）。本文件是玩法+数据+提示词+UI 的完整约定。

## 1. 核心机制：一个 NPC，两套档案

| 层 | 名字 | 内容 | 谁能看 | 作用 |
|---|---|---|---|---|
| 真相层 | `hidden` | 完整性格、真实目标、秘密、对每个人的真实印象、私下行事 | **只有模型**（每轮随 system 发送） | 决定她怎么说话、怎么行事——保证跨会话言行一致 |
| 视角层 | `profile` | 主控已解锁的信息：已感知性格侧面、生平条目、她表露出的对他人印象、最近可感知动向 | 玩家（详情页渲染） | 渐进解锁，全部要求来源可溯 |

纪律：真相层**永不**直接进入叙事或视角层；视角层只能收录本回合主控亲见、听说、合理推断的内容。
主控不可知的阴谋在她视角中保持"突然发生"（沿用世界书 §9）。

## 2. 存档 schema（挂在现有存档上扩展）

```json
"npcs": {
  "韦昭仪": {
    "known": true,                    // 认识才建档；未识之人不入册
    "metAt": "元朔元年三月",
    "name": "韦昭仪", "realName": "韦灵均", "rank": "昭仪", "age": 29,
    "faction": "含凉殿", "residence": "披香殿正殿",
    "maidCount": 8,
    "profile": {                      // ── 视角层（玩家可见，渐进解锁）
      "traits": ["谨慎", "念旧"],      // 已感知性格侧面，从往来中增加
      "biography": [                  // 生平时间线，条目带来源
        {"time": "元朔四年十一月中旬", "text": "咳疾渐愈，受崔明蘅温方之惠",
         "src": "亲见"},
        {"time": "元朔四年十二月中旬", "text": "宫中传她与太后娘家旧事有牵连",
         "src": "传闻", "doubt": true}
      ],
      "impressions": {                // 她对各人的印象——只记她表露/主控推断的部分
        "崔明蘅": {"tag": "盟谊", "note": "咳疾受她照拂，授藏证之道、开蒙琴艺"},
        "裴贵妃": {"tag": "疏远", "note": "宴集不同席，话不投机"}
      },
      "recent": ["咳疾渐愈，常召崔明蘅手谈"],   // 最近可感知动向
      "depth": "相知"                  // 解锁度：初识/相熟/相知/心腹（按条目数与互动深度定）
    },
    "hidden": {                       // ── 真相层（只发模型，永不渲染）
      "fullPersonality": ["谨慎", "念旧", "藏锋"],
      "goal": "维持与崔的盟谊；查清先皇后旧档，但不置于明面",
      "secrets": ["先皇后病中脉案经由她宫里的人手抄过一份"],
      "trueImpressions": {"崔明蘅": "可信，可用，仍需三分保留"}
    }
  }
}
```

- `name` 是宫中常用称谓（如「韦昭仪」），`realName` 是本名，两者一经确定不变；`rank` 是位份，可随升降更新。旧档没有 `realName` 时，前端按名讳哈希补一个稳定本名并在人物谱显示。

## 3. 解锁如何发生（每轮输出契约扩展）

模型每轮在现有 JSON 契约上新增 `dossier` 字段——**只收录本回合主控新获得的信息**：

```json
"dossier": [
  {
    "npc": "裴贵妃",
    "firstMet": false,
    "traits": ["记仇"],                      // 新增性格侧面（并集，不覆盖）
    "learned": ["冬至宴崔以『残雪缺月』答皇后，她侧目记怨"],   // 生平追加条目
    "impressions": {"崔明蘅": "记怨未发，正寻她的破绽"},        // 覆盖该条 note
    "src": "亲见"                            // 本批条目的来源总标：亲见/听说/传闻
  }
]
```

前端规则：
- `firstMet: true` → 新建档案页，弹"新相识"提示；
- `src` 为"传闻"的条目渲染时挂「传闻·存疑」标；
- 系统提示词中写明：传闻可与事实有偏差，dossier 只写实录与可感知内容，真相层信息不得写入。

## 4. 对系统提示词的修改（实现时追加到 01 模板）

新增"主持人纪律"第 13 条 + 输出契约补 `dossier` 字段，要点：

1. 每个 NPC 持有双层档案：hidden 是你的扮演依据（言行须符合其完整性格、目标、真实印象与秘密）；
   profile 只记录主控已感知内容，来源须标亲见/听说/传闻。
2. 言谈风格由「完整性格 × 对交谈对象的真实印象」即时生成，同一 NPC 对皇后与对低位妃嫔说话方式应不同。
3. 不得把 hidden 层的动机、秘密写进正文、dossier 或任何主控可见处；到期引线仍须兑现（沿用现有纪律 7）。
4. dossier 只写本回合新解锁，已解锁内容不重复上报。

## 5. 言行驱动的工程含义

- 真相层随存档持久化 → 跨会话一致；每轮随 system 全文发送 → 模型扮演不漂移。
- 龙套 NPC（宫人、低位妃嫔）只建一行简档（姓名/职司/一句印象），不展开双层，控制提示词体积。
- 核心 NPC 生平条目超 20 条时，旧条目压缩为一句概括（沿用叙事流压缩策略）。

## 6. UI（新增两个设计对象，已录入 CONTENT.md）

- **人物谱**（NPC 列表）：只列 `known` NPC；每行以本名为主、位份为小字浅色副标（位份会升降，本名不变），右侧显示关系标签；解锁度移入详情页；未深交者副标提示"只知名讳"。
- **NPC 详情页**：概况（称谓/位份/居所/派系）→ 性格侧面（已感知标签）→ 生平时间线（来源标）→ 印象（她对主控 / 她对他人，标注"据你所知"）→ 最近动向。
- 入口：查询面板「人物」分区 + 叙事/关系列表中点击人名直达。
- 详情页所有内容渲染自 `profile`；`hidden` 永不出现在任何 UI。

## 7. 已知边界（拍板记录）

- 导出 JSON 含 hidden 层 → 玩家自己能看到"后台真相"。单机游戏不加密，导出文件中该层标注
  「主持人视角 · 查阅即剧透」，靠自律。
- 解锁判据由模型执行（它知道本回合主控感知了什么），前端只做来源标注与渲染，不做内容审查。
- 死亡/出宫/失势 NPC 档案保留，状态标注变更，不作废。

## 8. 性情词表与头像适配（2026-11 追加）

- 性情只取 20 项固定词表：机敏、谨慎、隐忍、爽直、温厚、孤傲、执拗、柔婉、果决、多疑、淡泊、好胜、细腻、大气、怯懦、风趣、坚忍、清傲、圆滑、骄矜。每人 1—3 项。
- 同一人物不得重复、近义叠用或相斥。近义组至多取一：孤傲/清傲/骄矜；温厚/柔婉；隐忍/坚忍。相斥例：爽直↔隐忍、爽直↔圆滑、温厚↔孤傲、果决↔怯懦、果决↔多疑、淡泊↔好胜、大气↔多疑、骄矜↔隐忍。
- `profile.traits` 与 `hidden.真实性情` 同源：`hidden` 由同一组词条生成完整描述，`profile` 只写主控已感知的部分；`dossier.traits` 只可增补相容新词条，不得同义重复或覆盖。
- 头像由前端按身份、性别、年龄、性情分配：先过身份/性别/年龄硬条件，再按性情选最合气质的一张；全档尽量不重复。
- 皇帝头像固定为年轻俊朗的 1 号；28 号（肥硕老者）已停用，任何角色都不会再分到。温厚、柔婉、怯懦者不会分到高髻凌厉的 10 号；爽直、果决者优先 10/20 号。
